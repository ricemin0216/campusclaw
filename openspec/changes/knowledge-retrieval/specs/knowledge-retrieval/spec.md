# Spec Delta

## Purpose

为班级教学材料提供可解释、可追溯且由服务端强制班级隔离的关键词、语义和混合检索能力，使师生能够打开每个命中的原始材料。

## 本次增删记录

### 新增

- 增加 `OPENAI_API_KEY`、`MYSQL_PASSWORD` 与 `MYSQL_ROOT_PASSWORD` 的服务端配置、缺失时失败且不泄露秘密的契约。
- 增加 MySQL 应用账户和管理员账户密码须不同、首次初始化持久卷的行为，以及已有卷仅改 `.env` 不会自动轮换密码的场景。

### 删除

- 无。本次不改变既有切分策略、三种检索模式、0.35 阈值、班级隔离或检索结果字段。

## ADDED Requirements

### Requirement: 材料切分与向量索引
系统 SHALL 在教学材料成功写入后，将其 UTF-8 正文切分为带有材料标识、班级标识、从 1 开始的切片序号以及字符区间的切片，并为每个切片生成向量嵌入。系统 SHALL 默认使用约 800 个字符的窗口与 100 个字符重叠；教师上传时 SHALL 支持选择按换行、空行、句号或 Markdown 标题切分。启动时导入的种子材料 SHALL 始终采用默认窗口策略。

#### Scenario: 默认窗口切分教师材料
- **WHEN** 教师未指定切分策略并成功上传一份正文超过 800 个字符的本班材料
- **THEN** 系统以默认窗口和重叠创建有序切片，并为每个切片建立向量索引

#### Scenario: 选择替代切分策略
- **WHEN** 教师上传材料时选择换行、空行、句号或 Markdown 标题策略
- **THEN** 系统按所选边界创建有序切片并建立对应向量索引

#### Scenario: 启动时导入种子材料
- **WHEN** 系统启动并导入种子材料
- **THEN** 系统使用默认窗口策略切分种子材料，而不采用其他材料的可选策略

### Requirement: 切片正文与向量的分离存储
系统 SHALL 在 MySQL 中保存每个切片的正文、材料标题、班级标识、切片序号和字符区间，并为切片正文建立全文索引。系统 SHALL 在向量库中仅保存向量和定位该 MySQL 切片所需的标识及班级过滤元数据，且 SHALL NOT 在向量库 payload 中保存切片正文或检索摘录。

#### Scenario: 从检索命中构造摘录
- **WHEN** 任一检索模式命中一个切片
- **THEN** 系统从 MySQL 的该切片正文生成并返回摘录，而不从向量库读取或返回正文

### Requirement: 检索运行时秘密与 MySQL 初始化
系统 SHALL 仅从服务端 `.env` 或部署环境变量读取 `OPENAI_API_KEY`、`MYSQL_PASSWORD` 与 `MYSQL_ROOT_PASSWORD`。`MYSQL_PASSWORD` SHALL 用于应用连接 MySQL 的账户，`MYSQL_ROOT_PASSWORD` SHALL 用于 MySQL 管理员账户，并且二者 SHALL 使用不同的值。缺少任一必需值时，Compose 或应用 SHALL 启动失败，且错误信息 SHALL NOT 回显秘密值。MySQL 持久卷首次创建后，系统 SHALL NOT 因仅修改 `.env` 而自动轮换已存在的数据库账户密码。

#### Scenario: 使用服务端检索秘密启动
- **WHEN** 运维人员在服务端环境提供有效的 OpenAI API 密钥以及不同的 MySQL 应用和管理员密码，并启动新的 Compose 部署
- **THEN** 应用可读取检索配置，MySQL 使用提供的密码初始化相应账户，且任何客户端页面或 API 响应均不包含这些值

#### Scenario: 缺少检索或数据库秘密
- **WHEN** 运维人员未提供 OpenAI API 密钥、MySQL 应用密码或 MySQL 管理员密码中的任一值
- **THEN** Compose 或应用启动失败，失败信息仅指出缺失的变量名而不包含秘密值

#### Scenario: 修改已有 MySQL 卷的密码变量
- **WHEN** 运维人员仅修改已经初始化的 MySQL 持久卷所对应 `.env` 密码变量
- **THEN** 系统不将该修改视为已完成数据库密码轮换，运维人员需要保留原凭据或在备份后执行显式轮换或重建

### Requirement: 关键词检索模式
系统 SHALL 提供 `keyword` 检索模式，仅通过 MySQL 切片全文索引查询问句中直接出现在原文的词。该模式 SHALL NOT 调用嵌入服务或向量库，并 SHALL NOT 返回不包含查询词的切片以凑足结果数量。

#### Scenario: 关键词命中原文
- **WHEN** 本班成员以 `keyword` 模式查询直接出现在本班切片正文中的词
- **THEN** 系统仅返回包含该词的本班切片

#### Scenario: 关键词未命中
- **WHEN** 本班成员以 `keyword` 模式查询未出现在其本班材料中的词
- **THEN** 系统返回 `hits: []` 和“资料中未找到相关内容”，且不调用嵌入服务

### Requirement: 向量检索模式
系统 SHALL 提供 `vector` 检索模式，将问句转换为向量，并仅在本班切片向量中按余弦相似度检索。系统 SHALL 丢弃相似度严格低于 0.35 的候选，且 SHALL NOT 使用低于该阈值的候选补足结果数量。

#### Scenario: 语义相近但措辞不同的查询
- **WHEN** 本班成员以 `vector` 模式查询与本班切片语义相近但未直接复用原文措辞的问题
- **THEN** 系统返回相似度不低于 0.35 的本班切片

#### Scenario: 没有达到阈值的向量候选
- **WHEN** `vector` 模式的所有本班候选相似度均低于 0.35
- **THEN** 系统返回 `hits: []` 和“资料中未找到相关内容”

### Requirement: 混合检索模式
系统 SHALL 提供 `hybrid` 检索模式，同时执行关键词路径和向量路径，对通过各自有效性条件的候选按名次融合排序。两个路径均命中的同一切片 SHALL 获得双路命中提升，并排在仅由其中一路命中的切片之前；低于向量阈值的向量候选 SHALL 不参与融合。

#### Scenario: 双路命中优先
- **WHEN** 同一班级中有一个切片同时命中关键词和合格向量候选，另一个切片仅命中其中一路
- **THEN** 混合结果将双路命中的切片排在仅单路命中的切片之前

#### Scenario: 混合检索没有可信候选
- **WHEN** 关键词路径无命中且向量路径没有达到 0.35 的候选
- **THEN** 系统返回 `hits: []` 和“资料中未找到相关内容”

### Requirement: 可追溯的受保护检索结果
系统 SHALL 仅在服务端确认请求者属于目标班级后返回检索结果。每个命中 SHALL 包含材料标题、切片序号、以正文 Unicode 字符偏移表示的左闭右开字符区间、一段来自 MySQL 切片正文的摘录，以及可打开对应受保护材料的链接。请求者不属于目标班级时，系统 SHALL 返回 HTTP 403，且不返回命中、摘录或向量相关元数据。

#### Scenario: 本班成员查看命中并打开材料
- **WHEN** 已认证本班成员得到至少一个检索命中
- **THEN** 每个命中包含所需的追溯字段和可用于打开对应材料的受保护链接

#### Scenario: 跨班检索被拒绝
- **WHEN** 已认证用户查询不属于其所在班级的材料
- **THEN** 系统返回 HTTP 403，且不返回任何 `hits`、摘录、材料标题或切片元数据

### Requirement: 索引与材料生命周期一致
系统 SHALL 在材料删除时删除其 MySQL 切片和向量索引，并 SHALL 为已存在材料提供可重复执行的索引补建。任何成功完成的索引写入 SHALL 使对应切片在可用的检索模式中可检索；索引失败 SHALL 不得使过期切片继续作为有效命中返回。

#### Scenario: 删除已索引材料
- **WHEN** 本班教师成功删除一份已索引材料
- **THEN** 后续任一检索模式均不返回该材料的切片

#### Scenario: 补建已有材料索引
- **WHEN** 运维人员对已有材料执行索引补建
- **THEN** 系统为尚未索引或已失效的材料创建可检索切片，且重复执行不会产生重复命中
