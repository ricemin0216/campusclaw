# Proposal

## Why

教学材料需要按班级安全地共享给师生，而当前项目尚未定义身份验证、角色授权和班级数据边界。新增这些基础能力可防止未授权访问与跨班级泄露，并使教师能够将材料纳入可查询的知识库。

## What Changes

- 提供教师与学生的账号密码登录，以及对受保护页面和接口的身份验证。
- 为教师、学生定义服务端角色授权；拒绝学生调用材料上传接口。
- 将班级作为服务端数据访问边界，拒绝跨班级读取和操作材料。
- 允许教师上传教学材料并写入本班知识库，供本班材料列表查询。
- 上传仅接受 `.txt` 与 `.md` 文件，单个文件不得超过 10 MB；系统保留原文件及其 UTF-8 正文，供本班成员再次打开。
- 允许教师删除其所在班级的已上传材料，并同时移除关联的知识库记录和持久化文件。
- 规定密码使用强哈希存储，认证密钥只从服务端环境变量读取。
- 以 Docker Compose 提供可启动的应用，并暴露 `GET /health` 健康检查端点。

## Capabilities

### New Capabilities

- `identity-access-control`: 账号密码认证、受保护资源的身份验证、教师/学生角色授权及凭据与密钥安全要求。
- `class-knowledge-base`: 按班级隔离的教学材料上传、知识库写入和材料列表查询行为。
- `application-operations`: Docker Compose 启动约定和健康检查端点。

### Modified Capabilities

无；项目中尚无现有能力规范。

## Impact

- 新增认证、会话或令牌验证、角色与班级归属的数据模型及服务端授权中间件。
- 新增受保护页面的登录重定向行为，以及材料上传、正文查看、删除、查询与知识库持久化接口。
- 新增 Docker Compose 配置、服务端环境变量配置与 `GET /health` API。
- 需要选择密码哈希库及知识库/材料的持久化方案；这些实现细节将在设计中明确。

## Non-goals

- 不实现知识库检索、检索增强问答或任何对话助手能力。
- 不实现作业提交、自动或人工批改、成绩管理与反馈工作流。
- 不实现注册、找回密码、单点登录（SSO）、第三方身份提供商或管理员后台。
- 不实现生产级高可用、水平扩展、跨区域容灾或独立对象存储服务；本课以单个 Docker Compose 部署为目标。
