# Proposal

## Why

现有关键词问答只能拼接命中摘录，用户仍需要自行组织答案。基于同一网关的对话模型，可在严格限制为本班上传材料证据的前提下生成更连贯的回答，同时保留服务端产生的材料引用。

## What Changes

- 新增基于检索证据的 AI 知识问答接口与浏览器入口，不替换现有确定性关键词问答接口。
- 使用通过 `EMBEDDING_BASE_URL` 配置的 OpenAI 兼容网关，并配置 `CHAT_MODEL=doubao-seed-2-1-lite-260915`；复用现有 `EMBEDDING_API_KEY`，不向客户端暴露密钥。
- 仅将服务端筛选出的本班材料切片正文发送给模型，要求模型仅依据这些证据回答；无可信证据时不调用模型，直接返回“资料中未找到相关内容”。
- 返回模型答案以及服务端生成、不可由模型伪造的材料引用；维持 JWT Bearer、角色和班级隔离。
- 对模型超时、无效响应或上游失败返回受控错误且不泄露密钥、完整提示词或跨班资料。

## Capabilities

### New Capabilities

- `grounded-ai-knowledge-qa`: 将本班检索切片作为受控上下文，通过指定的对话模型生成带服务端引用的知识问答回答。

### Modified Capabilities

- 无。

## Impact

- 受影响代码：检索服务的证据选择、应用 API/浏览器工作区、环境配置与 Compose、运行说明和问答测试。
- 新增服务端配置：`CHAT_MODEL`；使用现有 OpenAI 兼容网关地址和 API 密钥。
- 新增外部模型调用与相应的网络延迟、用量成本和材料正文出站边界；不新增数据库 schema 或向量集合。
