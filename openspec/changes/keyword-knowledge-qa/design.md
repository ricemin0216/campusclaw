# Design

## Context

现有 `RetrievalService` 已可按班级从 MySQL 切片全文索引查询直接命中的文本，并通过 Bearer 守卫实施认证和成员关系检查。见 `proposal.md` 的动机；本设计不改变既有 `keyword`、`vector`、`hybrid` 检索契约。

## Goals / Non-Goals

**Goals:**

- 将中文问句和英文术语拆分成可解释的关键词，以关键词命中切片作为回答的唯一证据。
- 提供稳定的 API 响应、去重引用和浏览器展示，同时复用现有材料打开权限。
- 保持全程服务端班级过滤，且问答路径不调用嵌入 API。

**Non-Goals:**

- 不接入聊天大模型、提示词、流式输出、会话记忆、多轮对话或材料外推理。
- 不修改现有向量阈值、Qdrant 集合或嵌入服务配置。
- 不提供跨班汇总、管理员问答审计或答案人工编辑工作流。

## Decisions

### 确定性关键词拆分与停用词过滤

将输入规范化后提取连续英文/数字术语，以及中文文本中的相邻双字词；过滤常见疑问、语气和单字停用词，并按首次出现去重。中文双字词与当前 MySQL ngram 全文索引粒度一致，能在不添加分词服务的情况下保留“光合作用”这类术语的可检索片段。完全依赖空格拆分无法可靠支持中文；引入第三方中文分词会增加词典和运行时依赖，因此不采用。

### 逐关键词检索、去重证据与摘录式回答

问答服务逐个执行现有关键词全文查询，合并同一 `chunk_id`，保留该切片命中的所有关键词，并按命中关键词数、首次关键词位置和原有排序限制引用数量。回答由排序后的引用摘录组成，明确标注为“资料依据”，不进行自由文本改写。这样可保证每句输出可回到 MySQL 切片核验；调用现有混合检索再让模型总结虽能增加覆盖面，但违背关键词和无生成模型边界。

### API 与浏览器契约

新增 `POST /api/classes/<int:class_id>/questions`，请求 JSON 为 `{ "question": "..." }`，响应为 `{ "answer", "keywords", "citations" }`。引用沿用检索结果的材料标题、切片序号、字符区间、摘录和受保护材料 URL，并新增 `keywords` 字段。路由先执行既有 Bearer 认证和 `require_class_membership`，再进行任何关键词或材料查询。浏览器工作区新增问答表单，使用已有 `api()` 包装器附加内存 Token，并以 DOM `textContent` 渲染服务端文本。

### 无命中和错误处理

空白、非字符串或超过合理长度的问题返回 HTTP 400；没有关键词或没有证据均是正常 200 响应，固定回答为“资料中未找到相关内容”且引用为空。上游 MySQL 失败仍交由现有错误处理记录为服务错误，而非伪造无结果。

## Risks / Trade-offs

- [中文双字词可能产生泛化词并增加命中] → 停用词过滤、每词命中限制、按多关键词覆盖排序，且只返回实际包含关键词的正文摘录。
- [摘录不是自然语言总结] → 明确展示资料依据和引用，优先保证可追溯性；生成式总结留待独立变更。
- [关键词无法覆盖同义表述] → 该能力刻意使用直接词匹配；用户仍可使用现有 vector/hybrid 检索。
- [多次全文查询带来额外开销] → 限制关键词数、单关键词候选数和最终引用数，适合课程项目数据量。

## Migration Plan

1. 部署代码与测试，不变更数据库 schema、MySQL 切片或 Qdrant 数据。
2. 重新构建 app 容器；已有已就绪切片立即可参与问答，无需重建向量索引。
3. 若需回滚，移除问答路由与浏览器入口；现有检索、材料和认证数据保持不变。
