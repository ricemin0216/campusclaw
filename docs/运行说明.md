# 本地运行与容器运行

## 前置条件

- Python 3.12 或兼容版本；Docker Compose 用于容器运行。
- 真实密钥只放在本机 `.env` 或部署平台的环境变量中，禁止提交 `.env`。
- 向量检索需要支持 OpenAI Embeddings 兼容接口的服务端地址、密钥、模型和向量维度，以及 MySQL、Qdrant 的服务端连接配置。

## 本地运行

1. 创建虚拟环境并安装依赖：`python -m venv .venv`，随后运行 `.venv\Scripts\pip install -r requirements.txt`。
2. 在当前终端设置 `AUTH_SECRET`、`AUTH_TOKEN_SECRET`、`SEED_PASSWORD`、`EMBEDDING_BASE_URL`、`EMBEDDING_API_KEY`、`EMBEDDING_MODEL`、`EMBEDDING_DIM`、`CHAT_MODEL`、`MYSQL_HOST`、`MYSQL_DATABASE`、`MYSQL_USER`、`MYSQL_PASSWORD` 与 `QDRANT_URL` 环境变量。`CHAT_MODEL` 缺省时为 `doubao-seed-2-1-lite-260915`；`AUTH_TOKEN_SECRET` 必须是独立于 `AUTH_SECRET` 的强随机值，仅由服务端读取。
3. 运行 `python -m app`，再访问 `http://localhost:8000/health`。

初始化会创建 A 班、B 班、`teacher_a`、`student_a` 与 `student_b`；三个预置账户使用 `SEED_PASSWORD` 的哈希值，数据库不保存明文密码。

## Docker Compose

1. 将 `.env.example` 复制为 `.env`，把全部占位值替换为强随机值以及有效的 `EMBEDDING_BASE_URL`、`EMBEDDING_API_KEY`、`EMBEDDING_MODEL`、`EMBEDDING_DIM`。`CHAT_MODEL` 可保留默认的 `doubao-seed-2-1-lite-260915`，且不提交该文件。
2. 运行 `docker compose up --build -d`。
3. 运行 `docker compose ps` 确认 app、mysql、qdrant 均健康，再访问 `http://localhost:8000/health`。
4. 运行 `docker compose down` 停止服务；`app-data`、`mysql-data` 与 `qdrant-data` 卷会保留数据。

## JWT Bearer 登录与 API 调用

- 登录页使用同源脚本请求 `POST /api/auth/login`。令牌只保存在当前页面内存中；刷新页面后需要重新登录。不会创建认证 Cookie，也不会写入 URL、`localStorage` 或其他持久化浏览器存储。
- 登录 API 接受 JSON 或表单中的 `username`、`password`，成功时返回 `access_token`、`token_type: "Bearer"` 与 `expires_in`（默认 3600 秒）。旧 Flask 会话 Cookie 不再可用于认证。
- 所有受保护 API 都需要请求头 `Authorization: Bearer <access_token>`。例如，PowerShell 中可先保存登录响应的 `access_token`，再使用该请求头调用 `GET /api/me`、`GET /api/classes/<class_id>/materials` 或材料下载接口。
- 调用 `POST /api/auth/logout` 并携带该请求头会撤销当前令牌；重复调用安全且返回成功。登出后同一令牌访问任何受保护 API 都会得到 HTTP 401。令牌签名使用服务端 `AUTH_TOKEN_SECRET`，切勿将它放入前端代码或提交到版本库。

## 材料索引与检索

- 上传 `.txt` 或 `.md` 时默认使用 `semantic`：优先按 Markdown 标题、中文序号标题（如“二、”）和空段落聚合为约 400 字的切片；单个超长段落才退回 400 字窗口、60 字重叠。也可手动选择 `window`、`line`、`blank_line`、`sentence` 或 `markdown_heading`。网页上传表单提供这些选项。
- 可将种子文件放在 `seed_materials/<class-code>/`，例如 `seed_materials/class-a/lesson.md`。启动导入也使用默认 `semantic` 策略，且同内容文件不会重复导入。
- 对已有材料运行 `flask --app app reindex-materials`，使其采用当前默认切片策略并补建索引；该命令可重复运行。若更换模型或 `EMBEDDING_DIM`，先删除 Qdrant 的 `material_chunks` 集合，再补建索引，避免混用不同维度的向量。
- 使用 `GET /api/classes/<class_id>/search?query=<问题>&mode=<keyword|vector|hybrid>` 检索。`keyword` 仅查 MySQL 全文索引；`vector` 丢弃低于 0.35 的余弦相似度；`hybrid` 优先双路命中。无结果时返回 `{"hits": [], "message": "资料中未找到相关内容"}`。
- 命中字段包含材料标题、切片序号、Unicode 字符区间、来自 MySQL 切片正文的摘录及受保护的材料打开链接；Qdrant 不存储正文或摘录。

## 关键词知识问答

- 使用 `POST /api/classes/<class_id>/questions` 提问，JSON 请求体为 `{"question": "光合作用需要什么？"}`，并携带 `Authorization: Bearer <access_token>`。
- 系统将问题拆分为中文双字词和英文/数字术语，过滤常见疑问词后只查询本班 MySQL 切片全文索引；问答不会调用嵌入服务、向量库或生成式聊天模型。
- 成功响应包含 `answer`、`keywords` 与 `citations`。每个引用包含命中关键词、材料标题、切片序号、字符区间、原文摘录和受保护材料 URL；回答仅由这些摘录组织而成。
- 没有可检索关键词或没有本班证据时，接口以 HTTP 200 返回 `{"answer": "资料中未找到相关内容", "keywords": [...], "citations": []}`。未认证请求返回 401，跨班请求返回 403。

## 基于资料的 AI 知识问答

- 网页通过同一个“知识问答”入口选择“AI 回答”（默认）或“原文摘录”，两种方式共享问题输入和引用展示。
- AI 证据检索将问题拆分成关键词，优先采用至少两个关键词共同命中的切片（单个关键词问题要求命中该关键词），与满足相似度阈值的向量结果融合，避免完整问句没有逐字出现在原文时漏掉资料。

- 使用 `POST /api/classes/<class_id>/ai-questions`，JSON 请求体为 `{"question": "光合作用需要什么？"}`，并携带 `Authorization: Bearer <access_token>`。材料工作区也提供独立入口；令牌仅留在浏览器内存。
- 服务端先以现有混合检索选取最多 5 个本班、已就绪的切片；每个切片最多发送 800 个字符，合计正文不超过 4000 个字符。发送给模型的资料会明确标为不可信参考数据，不能改变模型规则。其他班级正文、材料和任何 API 密钥绝不会发送给浏览器。
- AI 回答由 `CHAT_MODEL` 通过已有 `EMBEDDING_BASE_URL` 和 `EMBEDDING_API_KEY` 的 OpenAI 兼容 Chat Completions 服务生成。响应 `citations` 始终由服务端根据实际发送的切片构造，包含标题、切片、字符区间、摘录和受保护材料 URL；不采纳模型自行编造的引用。
- 无本班证据时接口以 HTTP 200 返回 `{"answer": "资料中未找到相关内容", "citations": []}`，且不会调用对话模型。模型超时、鉴权、限流或上游响应异常时返回 HTTP 502 `{"error":"ai_answer_unavailable"}`，不回显密钥、完整提示词或上游正文。需要完全确定、无需模型调用的结果时，继续使用 `/questions` 关键词知识问答接口。

## 测试

运行 `pytest` 执行登录、角色授权、班级隔离、上传入库、切分、索引和三种检索模式测试。测试使用 fake OpenAI/Qdrant 客户端，不调用真实 OpenAI 服务。

可选的真实问答对照测试：在 PowerShell 运行 `Get-Content -Raw tests/manual_qa_comparison.py | docker compose exec -T app python -`。它使用已有 A 班《守则》、服务端演示账户和已配置网关，对比旧 800 字窗口／完整问句检索与当前语义切片／关键词融合检索，检查引用可打开、无关问题空回答和跨班 403；不修改存储的材料或索引。

2026-10-01 实测：考试诚信、校园欺凌、网络使用三道问题的预期要点命中由旧路径 2/3 提升到当前路径 3/3；原先漏答的网络问题现回答“不浏览、不传播不良信息，不沉迷网络游戏”。这说明该样本的证据召回改善，不能据此推断模型整体能力增强。

## 智能体、技能、会话与流式回答

- 教师可以在“技能管理”中提交单文件技能定义，并在“智能体管理”中设置角色提示词、启停状态以及绑定的本班技能和材料。学生只能列出并选用本班已启用的智能体；教师专属写接口对学生返回 403。
- A、B 班默认学习助手均预置数学解题、语文解题、古诗词讲解与推荐、英语词义例句与搭配、汉字词语学习、生活科学探究六项技能。预置过程可重复执行且不会产生重复记录；教师仍可创建更多本班技能。
- 技能文件以空行分隔元数据和说明，支持“名称、适用条件、资料、工具、启用”字段；工具仅允许 `knowledge_search`。用户可在新建会话时多选要加载的技能，也可在当前会话中更新选择；服务端只接受教师为该智能体开放且当前启用的技能。路由仅在用户已加载的技能中按关键词确定性计分，最多选择一个技能。
- 新建会话必须选择本班已启用的智能体。会话归属于当前用户并锁定智能体编号与用户选择的技能；智能体后来停用不影响已有会话，但新会话不能再选择它。教师移除绑定或停用技能后，该技能不会继续参与回答；材料绑定在每次提问时重新读取，修改后立即生效。
- `PATCH /api/conversations/<conversation_id>/skills` 供会话所有者调整后续提问要加载的技能，空数组表示只使用智能体基础能力；其他用户访问该会话仍统一返回 404。
- `POST /api/conversations/<conversation_id>/messages` 返回 `text/event-stream`，事件顺序为 `meta`、多个增量 `delta`、`done`，生成中途失败时返回 `error`。`meta` 最先给出命中技能和服务器生成的引用列表；响应同时设置 `X-Accel-Buffering: no`。
- 每轮只把最近 6 条有效消息送入模型，每条最多 500 字；检索仅限智能体绑定材料，最多使用 4 个切片。没有命中资料时仍按智能体与技能作答，但引用为空，输出中的 `[n]` 编号会被移除。
- OpenAPI 描述位于 `/api/openapi.json`，Swagger 页面位于 `/swagger`。主要接口包括智能体、技能、会话读取/创建及 SSE 提问。

## MCP 工具接入

- `mcp-server/` 与主应用同仓，由 Compose 以 `mcp-demo` 服务启动，公开容器内的 `GET /health` 和带 Bearer 鉴权的 `POST /mcp`。它实现 `initialize`、`tools/list`、`tools/call`，并提供 `formula_hint`、`unit_convert` 两个工具。
- 在 `.env` 配置 `MCP_AUTH_TOKEN` 后，Compose 会把同一个运行时令牌分别注入主应用和 `mcp-demo`，不会写入镜像或前端。主应用使用 `AUTH_SECRET` 派生的加密密钥保存登记令牌，任何 API 响应均不返回令牌。
- A 班会自动登记名为 `campus-tools`、地址为 `http://mcp-demo:8090` 的演示服务器。教师进入“MCP 工具”点击“连接”即可完成握手和工具发现；也可以填写名称、Base URL 和令牌登记或更新其他服务器。
- 技能“工具”字段支持 `knowledge_search` 和 `工具名@服务器名`，例如 `knowledge_search,formula_hint@campus-tools`。保存时服务端校验服务器必须属于本班、处于已连接状态且工具已在缓存中；断开会清空缓存。
- 学生问题命中技能后，主应用使用服务器端令牌调用 `tools/call`。成功文本只作为用户消息中的外部数据交给模型，不作为系统指令；SSE `meta.tool_calls` 返回工具引用和 `ok`、`denied` 或 `error` 状态。
- 教师可在“MCP 工具”查看最近 100 条本班审计，记录调用用户、`tool@server`、状态和时间。管理接口均只允许本班教师，跨班资源继续使用既有服务端边界。
- MCP API 回归可运行 `python apitest/run_all.py`；结果写到被 Git 忽略的 `apitest/report.html`。MCP 相关接口也已加入 `/api/openapi.json` 和 `/swagger`。
